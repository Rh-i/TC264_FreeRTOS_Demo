# 技术精华提炼

## 1. 数据丢包 / 错包 / 回报处理

### 1.1 接收链路的四级防丢设计

| 层级 | 设计 | 作用 |
|------|------|------|
| 硬件层 | 接收中断优先级高于周期性控制中断（30/31 > 24/25） | 杜绝控制中断嵌套延迟接收处理导致的硬件 FIFO 溢出 |
| 缓冲层 | 软件 FIFO 扩容至 256B（16 帧），写满失败不静默丢弃 | 峰值突发有缓冲余量，且每次溢出都累计计数可诊断 |
| 唤醒层 | FIFO 非空即发信号量、唤醒后循环消费直到不足一帧 | 消除"一次唤醒只解析一帧"造成的积压跟随延迟 |
| 解析层 | 逐字节状态机扫描帧头，失步时每次只丢弃 1 字节 | 避免 2 字节步长扫描导致的奇数偏移连环丢帧 |

### 1.2 错包处理

- **三重校验**：帧头对（双字节）+ 帧尾对（双字节）+ 前 13 字节累加和低 8 位；任一不匹配整帧丢弃，解析状态无条件复位到帧头扫描，不污染下一帧；
- **异常自愈**：连续重复帧头时保留最新帧头继续同步（处理"帧中夹帧头"场景）；任何失步均可在下一字节边界重新锁定，无需整包重传协议；
- **诊断闭环**：溢出丢字节计数持续累计，为"丢包发生与否"提供现场判据（当前未接入查询命令，属已知遗留）。

### 1.3 回报（ACK）机制

- 所有设置/运动/按键命令均回 16 字节响应帧（状态码 + 原命令码）；查询命令回数据载荷帧；
- 响应帧与上报帧、调试打印共享同一发送互斥锁串行化，杜绝多发送者字节交错；
- 编译期开关可整体关闭回报；
- **已知边界**：协议无序号字段，连发丢帧时 ACK 与请求会错位对应；上位机须按"先发先得"配对，或后续引入 seq。

## 2. 模块架构

自底向上五层，依赖方向单向向下：

```
App/Service   入口、任务定义、中断服务、全局初始化
   ↑
Protocol      16字节帧协议：状态机解析、命令分发、响应
   ↑
Module        控制逻辑：遥控控制 / 自动控制（模式分发）
   ↑
Device        设备抽象：电机、舵机、遥控接收机（结构体+接口）
   ↑
Bsp           板级驱动：串口、编码器、PWM、按键/LED/蜂鸣器
   ↑
OS            内核（仅 CPU0 运行）；CPU1 裸机
```

**组织原则**：
- 每类设备 = 结构体实例 + `init/update/set_*` 三件套接口，全局单例；
- 配置与逻辑分离：波特率、引脚、中断优先级、协议命令码、PID 参数全部集中为宏/枚举；
- 编译期特性开关：板级测试模式开启/关闭时，测试接口退化为空宏，零运行时开销；
- 硬件资源绑定清晰：串口 0/2 调试、串口 1 遥控、串口 3 上位机协议；定时器分别承担编码器解码与 PWM。

## 3. 核心任务逻辑（简略）

### 3.1 控制权切换

三段开关 + 在线状态决定唯一控制源：
- **手动**：遥控接管，油门摇杆映射速度、转向摇杆映射舵机，副开关选择滑行/刹停；
- **无控制**：立即刹停 + 舵机回中；
- **自动**（默认）：上位机协议接管；
- **遥控离线强制回自动**（安全回退）。

所有模式共享同一 20ms 闭环周期，保证任意切换瞬间 PWM/角度连续。

### 3.2 协议控制链路

中断收字节 → FIFO → 信号量唤醒协议任务 → 状态机解帧校验 → 更新目标状态（速度/时间/角度/模式）→ 立即回 ACK → 自动模式下按模式下发电机指令。

关键语义：仅改变电机运动的命令触发执行；查询类、舵机类命令不触碰电机状态（舵机角度由 20ms 周期直接应用）。

### 3.3 电机速度环

- 20ms 固定周期；编码器增量 → 物理速度换算（轮周长/分辨率/周期）→ 位置式 PID → PWM + 方向引脚；
- 输出限幅 + 积分限幅（限幅值为输出限幅的 35%）；
- 三种运动状态：停止 / 纯速度（持续到被覆盖）/ 速度+时间（基于系统 tick 计时自动停止）；
- 停止时 PID 复位，方向归位，PWM 清零。

### 3.4 遥控链路

- SBUS 私有帧（100000 波特、8E2），25 字节固定帧，16 通道 × 11bit 位提取；
- 摇杆通道带零飘偏移校准与死区归一化；开关按阈值分段判定；
- 在线判定双保险：帧标志字节 + 距上次有效帧超时计数。

## 4. 关键设计决策

1. **前后台 + RTOS 混合**：实时性强、周期确定的动作（按键扫描、遥控解析、电机闭环、舵机输出）放中断；非实时业务（协议解析、任务执行、测试流程）放任务。二者以信号量/队列解耦，避免任务优先级耦合实时链。
2. **发送统一加锁、接收短临界区**：发送侧互斥锁（带优先级继承）串行化所有发送方；接收侧读 FIFO 时短暂全局关中断（拷贝仅几十纳秒），消除中断与任务并发改指针的竞态。
3. **中断优先级全局规划**：所有用户中断由 CPU0 服务、各优先级互不相同；串口接收优先级压过控制中断，且压在上限 31 之内以保证中断内可安全唤醒任务。
4. **多帧一次性消化**：唤醒后循环解析至 FIFO 不足一帧，防止二值信号量多次 give 合并导致积压只能随新字节缓慢消化。
5. **安全回退**：遥控离线自动切回协议控制；无控制模式立即刹停回中；协议紧急停止命令覆盖式清零速度与时间。
6. **可诊断性**：溢出计数、错误中断挂接、串口回显调试打印、vofa 波形上报任务（方波/正弦激励调参）构成三级调试手段。
7. **已知技术债**（保留记录，勿踩坑）：
   - 协议无序号 → 连发 ACK 错位；
   - 手动模式断电丢帧边界可能误判在线 → 断电前须将三段开关拨离手动位；
   - 看门狗被显式关闭，CPU1 尚未承载任何功能；
   - 舵机中位未完全标定。
